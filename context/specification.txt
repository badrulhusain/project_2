PRODUCT
EventSense is a campus event platform that fixes miscalculation of food, seating, parking and electricity. Admins create events (venue, capacity, safety limit, menu, parking zones, equipment, cutoffs). Attendees (Next.js client) book a seat, pre-order food and reserve parking. The server turns those bookings into an attendance forecast and recommends food quantities, seat/parking utilization and a power-load plan. On event day it supports QR check-in, QR food collection, waitlist auto-promotion and timed notifications. After the event it compares planned vs actual and recalibrates show-up rates.

BUSINESS RULES
- Effective capacity = min(capacity, safetyLimit). Booking runs inside a Prisma $transaction with row locking (SELECT ... FOR UPDATE via $queryRaw on the Event row) so the last seat can never be double-booked. If full -> WAITLISTED with position. Booking closed after bookingCutoffAt or when event not PUBLISHED/LIVE.
- Parking: same transactional approach per zone; if zone full return 409 with a clear message (booking still succeeds without parking only if client omitted zone).
- Cancel: frees seat/parking and promotes the first WAITLISTED booking, enqueueing an email + notification.
- Cron every minute: (1) send due Notifications (email each booked user via Nodemailer or Outbox), set sentAt; (2) for events past seatReleaseAt, mark CONFIRMED-but-not-checked-in bookings RELEASED and promote waitlist.
- Auto-generate default notifications when an event is published: "Booking confirmed" per booking, food-timing reminder 1h before startAt, "Last call for food" at foodCutoffAt.

PLANNER LOGIC (pure functions in planner/forecast.ts, fully unit-tested)
1. Rates: load CalibrationStat for (event.type, event.isPaid); if missing use defaults: paid showRate 0.93, free showRate 0.62, walkInRate 0.05 (paid) / 0.10 (free), claimRate 0.85 (paid) / 0.75 (free). Treat these as configurable constants.
2. booked = count of CONFIRMED + CHECKED_IN. likely = round(booked*showRate + booked*walkInRate). sd = sqrt(booked*showRate*(1-showRate)). low = max(0, round(likely - 1.65*sd)), high = round(likely + 1.65*sd). Return {booked, low, likely, high, showRate, walkInRate} and a plain-English explanation string.
3. Seats: utilization = likely/effectiveCapacity; status OK (<0.85), TIGHT (0.85-1), OVER (>1); suggest "open waitlist"/"release more seats"/"venue too large" messages. Also overbookSuggestion for free events.
4. Food, per item: ordered = sum of quantities; walk-in share = item's ordered share of total orders * (walkIn count * 0.5); recommended = ceil(ordered*claimRate + walkInShare); low/high scaled by low/high attendance ratio; add 5% buffer to recommended. Output {item, ordered, recommended, low, high, risk: 'WASTE_RISK'|'BALANCED'|'SHORTAGE_RISK'} and overall comparison vs "manual guess" = total bookings (so the UI can show meals saved) and estimated cost saved when unitCost exists.
5. Parking: per zone expected demand = bookedInZone * showRate scaled; utilization + status.
6. Power: build a timeline in 30-minute steps from event start to end. For each Equipment active at that step: kW = watts*count/1000, multiplied by max(0.3, likely/effectiveCapacity) when occupancyScaled. Return points [{time, loadKw}], peakKw, peakTime, powerLimitKw, headroomKw, status OK (<80% of limit) | WARNING (80-100%) | OVERLOAD (>100%), plus a recommendation (e.g. stagger the AC start).
The planner endpoint returns {attendance, seats, food, parking, power, generatedAt}.
